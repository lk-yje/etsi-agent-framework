# 真机阶段变更与证据保全原则

本文件约束迁移到内网工作机之后的文件修改、测试动作与证据处理。目标是：可以为真实环境做必要配置，但任何配置改变、测试输入改变或 DUT 状态改变都不应被伪装成原始证据。

## 1. 不变边界

1. **不改仓库共享映射**：不得为工作机修改或提交 `skills/path-mapping.json`。工作机工具位置只放在仓库外的私有 `PATH_MAPPING` 文件，路径由环境变量指向。
2. **不改标准、skill、recipe 来迁就测试结果**：条款速查、裁决规则、Phase 定义和 evidence schema 的任何修改，都必须作为独立代码/规则变更审查；不得在一次真机 run 过程中临时改写后继续使用同一 workspace 的结果。
3. **不覆盖输入或证据**：同一 workspace 中，不允许用不同的 IXIT、old/tampered 固件或目标配置覆盖既有 manifest。来源 hash 变化、解析器变化、固件角色变化或 DUT 固件版本变化，必须创建新 workspace/new run。
4. **不把控制台登记删除当作证据删除**：移除 run 仅清 `.runs.json` 注册；workspace、原始 artifact、receipt、报告和 PCAP 保持不动。
5. **不把 mock/离线预检当真机结论**：真实 `tool receipt`、PCAP、Burp history、命令输出、截图和人工记录缺失时只能为 `INCONCLUSIVE` 或 `PENDING_MANUAL`。

## 2. 允许的工作机私有变更

以下可在工作机实施，但都必须记录操作者、时间、原因和变更前后值（敏感值仅记录 hash/掩码）：

| 变更类别 | 允许位置 | 留痕要求 |
|---|---|---|
| 工具路径、输入/固件根目录 | 仓库外私有 mapping、当前 PowerShell 环境 | `environment_snapshot.json` 记录解析结果与版本；不写 Token |
| DUT IP、Burp host/port、无 Playwright 开关 | 当前 workspace 的 `run_config.json` | run id、时间、非 secret 值；DUT IP 覆盖优先于 IXIT 仅用于本 run |
| IXIT/XLSX、old/tampered 选择 | 外部受控源目录 + workspace manifest | 原路径、大小、SHA-256、解析器版本/派生产物 hash；原件不复制、不修改 |
| Pipeline 生成物 | 当前 workspace | 仅追加新的 state/events/receipt/evidence/report；不得手工编辑既有 evidence JSON 伪造结果 |
| 代码/skill/recipe 修复 | 新的受审查代码版本 | 停止当前 run；记录变更集与原因；在新 workspace 重新开始 |

## 3. DUT 与代理的最小变更原则

- 先取得书面授权与维护窗口，再扫描、登录、修改配置、上传固件或执行主动测试。
- 为测试而改变 DUT 配置（账户、代理、自动更新、网络、固件、恢复出厂等）前，记录基线；完成后按批准的恢复步骤复原，并把恢复结果记录到 checklist/人工记录。
- old 与 tampered 固件必须角色分离、hash 固定。上传/尝试本身可能改变 DUT 状态，必须有回滚包、恢复负责人和明确的停止条件。
- Burp 上游代理只在 Traffic 尝试期间配置。无论完成、跳过、失败或取消，均核对“xray/tshark 清理 → Burp 恢复”；恢复失败即为未收敛，不应开始下一 run。
- 安全停止是**取消**而不是暂停：它不会强杀 PID，但 run 进入 `cancelled` 后不得继续或 resume；已有部分产物保留为部分证据，后续条款、审计和报告不应补跑到同一 run。

## 4. 每次 run 的变更记录最小字段

在工单或随 workspace 保存的人工记录中至少填写：

| 字段 | 内容 |
|---|---|
| run/workspace | run id、workspace 路径、代码版本/提交标识（如可用） |
| 测试范围 | DUT 识别信息、授权编号、开始/结束时间、操作者 |
| 输入基线 | IXIT 来源/派生 hash；old/tampered hash；工具版本快照 |
| DUT/代理变更 | 变更前后状态、实施人、批准人、回滚动作与结果 |
| 异常/停止 | 原因、何时请求取消、Traffic cleanup/Burp restore 是否完成 |
| 裁决证据 | recipe、receipt、artifact 路径/hash、expected/actual、人工复核人 |

## 5. 何时必须新建 workspace

出现以下任一情况，禁止在原 workspace 继续：IXIT 来源 hash 变更；固件样本或角色变更；DUT 固件/配置/型号变更；PATH_MAPPING 解析到的关键工具或版本变更；Traffic 未恢复 Burp；Pipeline 进入 `cancelled/failed/needs_review` 后准备重新执行；条款 recipe、skill、parser 或裁决规则变更。

新 workspace 可以引用已有原始文件，但必须重新登记 hash、重新生成 input manifest 和新的 run id。这样报告能区分“同一设备的另一次受控尝试”和“对旧证据的覆盖”。
