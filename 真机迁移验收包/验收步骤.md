# 内网真机验收步骤

## A. 授权与环境

- [ ] DUT IP、测试窗口、账户权限、固件操作许可和恢复负责人已在工单中确认。
- [ ] 私有 `PATH_MAPPING` 已由工作机维护者配置；仓库 `skills/path-mapping.json` 未被修改。
- [ ] `INPUT_ROOTS`、`FIRMWARE_ROOTS` 均指向工作机实际存在的受控目录。
- [ ] 控制台离线 preflight 已保存 `environment_snapshot.json`；tshark/xray/Burp 相关版本与路径可读。
- [ ] IXIT 引用已解析成功；manifest 含来源路径、来源 SHA-256、派生 JSON SHA-256 和解析器信息。
- [ ] old 与 tampered 固件引用均有路径、SHA-256、大小；其角色未互换。

## B. Traffic 3.1

- [ ] Burp 代理链确认：浏览器 → Burp:8080 → xray:7778 → DUT；备份/恢复操作可审计。
- [ ] UI 显示 `WAITING_START` 且 tshark/xray 均为运行状态，再点击“开始操作”。
- [ ] 用户在同一窗口内从头到尾连续完成全部计划内操作；UI 不要求逐项勾选、步骤标签、说明或时间点。
- [ ] UI 显示 `WAITING_FINISH` 后才点击“完成采集”。
- [ ] 验证停止顺序：xray/tshark 清理 → Traffic Intelligence → 兼容输出 → Burp 恢复 → `COMPLETE` 或如实的 `BLOCKED/FAILED`。
- [ ] `capture.pcap` 非空，`traffic-intelligence/manifest.json` 完整且散列校验通过；兼容输出失败不阻断主 Bundle，也不留下空目录/半成品。

## C. 安全停止与运行管理

- [ ] 点击“请求安全停止”仅创建取消请求，不强杀 PID。
- [ ] 页面依次出现“已请求取消 → Traffic 清理（停止 xray/tshark）→ 恢复 Burp 上游代理 → Pipeline 已进入取消终态”。
- [ ] 若停在非 Traffic 阶段，页面如实显示等待阶段安全点，不伪称 Traffic 已清理。
- [ ] 已终态 run 可“移除登记”；确认工作区、证据、报告和 PCAP 保持原路径且未删除。
- [ ] 不使用 `resume`；旧抓包、Burp 状态和 M1-M5 phase 幂等语义未定义前不得恢复。

## D. 条款、证据与报告

- [ ] 执行 `生成条款验收清单.py`，按生成表逐条签收 full/partial 条款。
- [ ] 每条自动化结果均核对 recipe、IXIT 表位、tool receipt、artifact、expected/actual 和 oracle。
- [ ] 概念性条款使用 IXIT 多表检索结果；信息不足为 `INCONCLUSIVE`，不由 LLM 补造事实。
- [ ] 手工条款保留步骤、人员、时间、截图/原始记录引用；不计入自动化通过率。
- [ ] HTML/Markdown/JSON 报告、条款证据包和下载包之间条款数、裁决、hash 一致。
- [ ] 由独立测试员抽取至少一条 full 与一条 partial，按报告复现逻辑复核。
