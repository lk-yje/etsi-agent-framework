# Pipeline 模式输出格式

> 被 `etsi-report-auditor/SKILL.md` 引用。

---

## Round 1 单模块审计

### GOOD

```
## {module_id} 审计结果: GOOD

{条款数} 条款三角对照一致，裁决准确。

观察项 (如有):
- ...
```

### NEEDS

```
## {module_id} 审计结果: NEEDS (第 {retryCount+1} 次)

### {clauseId}: {问题一句话}

| 三角定位 | Standard vs IXIT | Standard vs Evidence | IXIT vs Evidence |
| 问题 | {矛盾在哪里} |
| Mx 错误 | {错在哪 — 错位/忽略/过度/逻辑跳跃} |
| 补证 | {具体补什么维度 — 仅维度缺口，不写工具/参数} |

### 整体
{主要问题类型总结}
```

### FLAGGED

```
## {module_id} 审计结果: FLAGGED

经 2 次重派仍有以下问题:
{逐条列出}

以上条款由主线程最终裁定。
```

---

## Round 2 跨模块审计

### GOOD

```
## Round 2 审计结果: GOOD

全部 {N} 对跨模块关系一致，继承链完整，无矛盾。
```

### NEEDS (含审计师专业判断)

```
## Round 2 审计结果: NEEDS

### 跨模块矛盾清单与专业判断

| # | 模块对 | 矛盾描述 | 涉及条款 | 整合分析 | 建议 |
|---|--------|---------|---------|---------|------|
| 1 | M2 ↔ M3 | M2 判 SHA-256 但 M3 pcap 显示 HTTP 明文 | 5.1-3, 5.5-1 | {审计师对矛盾的整合分析：哪个模块的证据更可靠、矛盾根源在哪、是否因测试时间/条件差异导致} | 建议以 M3 pcap 证据为准，M2 修改 5.1-3 裁决 |
| 2 | M1 ↔ M3 | M1 记录端口 443 开放但 M3 未发现 TLS 握手 | 5.6-1, 5.5-1 | {分析} | {建议} |
```

> 矛盾跨模块，不重派 work-agent。审计师给出整合分析和建议，由用户做最终裁定。
