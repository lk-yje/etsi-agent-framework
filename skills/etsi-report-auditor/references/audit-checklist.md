# 逐条款审计清单

> 审计者在对每个条款做裁决审查时，逐条核对以下清单。
> 每个条款的"完整结论条件"见 [verdict-criteria.md](${DIR.SKILLS}\etsi-ts103701-report\references\verdict-criteria.md)。

---

## 审计清单使用说明

每个条款的审计，按以下框架执行：

```
1. 确认 ICS 声明
2. 确认报告裁决
3. 加载标准结论条件 (verdict-criteria.md)
4. 逐条件比对
5. 判别误判模式 (common-errors.md)
6. 评估证据 (evidence-standards.md)
7. 输出审计判定
```

## 5.1 不使用通用默认口令

### 5.1-1 唯一口令 (M C(1))

| 审计项 | 查什么 | 红色标志 |
|--------|--------|---------|
| 条件性前提 | 设备是否使用口令？ICS=Y 即前提成立 | ICS=N/A 却做了概念性测试 |
| 概念性 5.1-1-1 | 出厂默认外所有基于口令的认证机制，每个口令都是唯一的且非用户定义的 | 报告只说"随机生成"未验证实际唯一性 |
| 功能性 5.1-1-2 a) | 所有发现的认证机制都在 IXIT 中记录 | Nmap 发现额外认证接口但报告未记录/未对照 |
| 功能性 5.1-1-2 b) | 要求用户在使用前定义所有口令 | 报告未实际走一遍初始化流程验证 |
| 功能性 5.1-1-2 c) | 无非用户定义口令的生成与 IXIT 描述不同 | 报告仅依赖 IXIT 描述未做端口/协议扫描发现隐藏认证 |

| 概念性 5.1-2-1 b) | 无共同字符串/模式 | 口令含相同前缀（如"IPC-"）→ FAIL |
| 概念性 5.1-2-1 c) | 不与公共信息明显相关 | 口令可从铭牌/WiFi SSID/MAC 推导 |
